## Clean Code Lessons Learned

Some of the most important lessons about writing clean code in this subject:

- **Use meaningful, descriptive names** - variable, function, and class names should clearly express their purpose
- without needing a comment to explain them.
- **Follow the Single Responsibility Principle (SRP)** - each function and class should do one thing well; if you
- find yourself writing "and" when describing what something does, it probably needs to be split up.
- **Don't Repeat Yourself (DRY)** - if the same logic appears in more than one place, extract it into a reusable
- function so changes only need to be made once.
- **Use docstrings, not inline comments** - functions and classes should have docstrings that explain *what* they do;
- inline comments should explain *why*, not *what*.
- **Keep functions small and focused** - a function that fits on one screen is easier to read, test, and maintain than
- one that scrolls on forever.
